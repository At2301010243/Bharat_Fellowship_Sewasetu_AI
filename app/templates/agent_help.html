Using an AI assistant with Seva Setu

Seva Setu provides two secure MCP connections for compatible AI assistants. They are APIs, not web chat pages, so opening an MCP URL in a browser will show an OAuth token message.

Connect Seva Setu to ChatGPT

  1. Open ChatGPT in a desktop browser.
  2. Open Settings, then open Apps, Connectors, or Developer mode, depending on the ChatGPT version.
  3. Choose Create app, Add custom app, Add connector, or Add remote MCP server.
  4. Give the app a name such as Seva Setu Citizen.
  5. In the Server URL, MCP URL, or Endpoint field, paste the provided link in the form for the role you want to connect. Do not paste the portal home-page link.
  6. Choose OAuth when ChatGPT asks for authentication. Do not choose API key or unauthenticated access.
  7. Save the app and choose Connect or Sign in.
  8. Complete the Seva Setu sign-in and approve the consent request.
  9. Return to ChatGPT, enable the new app in a new conversation, and open the app details to confirm that tools are listed.

Which app should you create?

  • Seva Setu Citizen: choose this for a citizen or a family helper. It can check eligibility, create an application, upload age proof, submit, read status, and withdraw a pending application.
  • Seva Setu Officer: choose this for a block officer. It can view the queue, inspect applications, and approve or reject with a reason.

Create two separate apps if you need to test both roles. Do not put the citizen and officer MCP links into one app.

Sign-in and consent

  1. For citizens, enter the mobile number and the OTP shown in the SMS gateway console, then approve the citizen access request.
  2. For officers, sign in with the departmental admin username and configured administrator password, then approve officer access.
  3. Citizen and officer access are separate. A citizen connection cannot use officer queue or decision tools.

Important: successful login at Application Status or Admin does not automatically log an AI assistant in. The assistant performs its own OAuth consent flow.

Test the citizen connection

After connecting the citizen endpoint, ask ChatGPT:

List the available Seva Setu citizen tools and briefly explain what each one does.

It should show tools for scheme information, eligibility, application drafts, age-proof upload, submission, status, and withdrawal. Then test the complete workflow with:

Use the Seva Setu citizen tools to check eligibility for a demo applicant:
Name: Kamala Das
Date of birth: 10/06/1945
Village: Sonari village
Block: Sonari
Gender: Female
Marital status: Widowed
Do not submit the application yet.

Continue only after reviewing the result:

Start a Seva Setu application draft, update it with the confirmed applicant
details, upload the selected demo JPG or PDF as age proof, and show me the
validation result. Do not submit until I explicitly confirm.

For a real submission, use an authentic accepted age-proof document. A demo image may test the upload transport, but it does not prove age or document authenticity.

Test the officer connection

Use a separate ChatGPT conversation with only the officer connection enabled:

Use the Seva Setu officer tools to show the pending application queue for
Sonari and Rajapara. Do not approve or reject anything.

Then inspect a queue item:

Inspect application ID <APPLICATION_ID> and show its details and audit
history. Do not make a decision.

Approval or rejection must always be an explicit officer action. A rejection must include a recorded reason.

Pilot rules

  • The pilot supports only Sonari and Rajapara.
  • Age proof, eligibility validation, duplicate checks, identity, consent, audit logging, and the 15-day deemed-approval rule are not bypassed.
  • The existing Seva Setu portal remains the system of record. Agent-created applications appear in the normal citizen and officer portals.

  • Officer MCP discovery

Troubleshooting

  • The form asks for a URL: paste the provided citizen or officer MCP link in the form, including /mcp/citizen or /mcp/officer. Do not paste an OAuth discovery link, the website home page, or a localhost link.
  • 401 access token required: expected when opening an MCP URL directly in a browser. Connect through ChatGPT so it can complete OAuth.
  • No tools available or action discovery failed: remove the connector, add it again, complete OAuth again, and start a new ChatGPT conversation. ChatGPT may cache the tool list.
  • Unknown application: confirm that the endpoint uses the current public HTTPS URL and not an old Codespaces or localhost URL.
  • 502 or timeout: confirm that port 8000 is Public in the VS Code Ports panel and test the public home page before reconnecting ChatGPT.

This portal does not contain a built-in AI chat model. It provides the official, OAuth-protected MCP channel that an external assistant such as Claude Code or another MCP-compatible client uses.
